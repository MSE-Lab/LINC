## 概述

Step 3 是 LINC 框架的核心阶段,负责将各基因组的局部代表序列增量并入全局代表库,构建全局同源关系网络。

---

## 输入

- **数据**:
  - `GenomeInfo`: 基因组元信息
  - `GenomeIntraResult`: 基因组内聚类结果 (局部代表序列)
- **参数**:
  - Cutoff-I, Cutoff-II, max_per_cluster

## 关键设计决策

### 1. Order-D 确定性排序

**为什么需要确定性排序?**

```
问题: 如果随机排序或按文件读取顺序

后果1: 结果不可复现
  - 两次运行相同数据,可能产生不同结果
  - 科学可复现性受损

后果2: 早期错误固化
  - 小基因组先处理,形成欠成熟簇结构
  - 后续大基因组的基因被迫并入错误簇
  - 几乎无法逆转

Order-D 解决方案:
  - 大基因组优先: 全局代表库早期达到最大覆盖
  - 高多样性优先: 充分捕获序列变异
  - 字典序兜底: 任何情况排序唯一
```

### 2. 双阈值解耦机制

**传统方法的困境:**

```
单一阈值问题:
  - 阈值高 (80%): 召回低,远缘同源被过滤
  - 阈值低 (40%): 精度低,旁系同源被错误合并

无法同时保证"找回远缘同源"和"排除旁系同源"
```

**LINC 的解决方案: 双阈值解耦**

```
Cutoff-I (纳入阈值,宽松,默认 50%)
  ├─ 语义: "是否属于同一同源家族?"
  ├─ 判定: identity ≥ Cutoff-I 且 coverage ≥ Cutoff-I (双向 qcov & scov)
  ├─ 作用: 决定 SSN 边建立 / 跨簇合并
  └─ 目标: 保召回广度

Cutoff-II (高置信阈值,严格,默认 80%)
  ├─ 语义: "是否与现有代表高度保守?"
  ├─ 判定: identity ≥ Cutoff-II 且 coverage ≥ Cutoff-II (双向 qcov & scov)
  ├─ 作用: 决定是否新增为代表
  └─ 目标: 保注释精度

两者是**语义完全不同的**两种生物学判定,不是"松/严"的参数选择
```

### 3. 自适应多代表决策树

#### 路径①: 零簇命中

```
新代表 vs 全局代表库 → 0 个命中

动作: 创建新簇,该代表作为初始全局代表

示例:
  新基因 X 在所有已有代表中找不到同源伙伴
  → 创建簇 {X}, 代表 {X}
```

#### 路径②: 单簇命中

```
新代表 vs 全局代表库 → 命中簇 A

├─ 达到 Cutoff-II (≥80%)
│   动作: 沿用已有代表,不新增
│   语义: "X 与代表 A1 高度保守,无需新增代表"
│
└─ 仅达 Cutoff-I (50%-80%)
    动作: 增补为代表 (≤max_per_cluster)
    语义: "X 可能携带结构变异,是新的功能亚型"
```

#### 路径③: 跨簇命中 (≥2 簇)

```
新代表 vs 全局代表库 → 命中簇 A, B

├─ 有 Cutoff-II 命中
│   动作: 只合并,不新增代表
│   语义: "A 和 B 应该合并,但 X 与已有代表足够保守"
│   目的: 纠正碎片化
│
└─ 均仅达 Cutoff-I
    动作: 合并,且新增为代表
    语义: "A 和 B 是远缘家族,X 连接了它们"
    目的: 捕获连接远缘家族的新变体
```

### 4. 一次比对,全局复用

**关键设计原则:**

```python
# 新代表与全局库比对后,同一比对结果复用三次:
hit = align(gene_X, global_library)

# 1. 簇归属判定: X 属于哪个簇?
cluster = determine_cluster(hit)

# 2. 合并触发: 是否需要跨簇合并?
if hit.clusters > 1:
    trigger_merge(hit)

# 3. 代表裁决: 是否新增为代表?
if hit.any_reaches_cutoff_ii:
    skip_add_representative()
else:
    add_as_representative()
```

**优势:**
- 避免二次比对的计算开销
- 避免二次比对可能引入的不确定性
- 裁决基于固定不变的原始比对分数

## 搜索空间压缩

**增量架构的核心效率来源:**

```
传统方法:
  新基因组 N 个基因 vs 总基因 M 个基因
  比对次数: N × M = O(N×M) ≈ O(N²)

LINC 方法:
  新基因组的局部代表 R 个 vs 全局代表库 G 个
  比对次数: R × G = O(R×G)

压缩效果:
  R << N (代表数 << 基因总数)
  G << M (全局代表 << 总基因数)

实际案例:
  - N = 5000 基因
  - R = 750 代表 (压缩率 15%)
  - M = 10000 总基因
  - G = 1500 全局代表

  传统: 5000 × 10000 = 50,000,000 次
  LINC:  750 × 1500   =   1,125,000 次
  加速: 44x
```
